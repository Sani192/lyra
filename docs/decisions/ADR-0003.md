# ADR-0003: Why Integrations Are Contract-Driven

## Maturity Metadata

**Status:** Approved.

**Intended Use:** Authoritative architecture decision; safe for implementation decisions within its documented scope.

## Status

Accepted.

## Context

Lyra connects to diverse external applications (restaurant, hotel, CRM, etc.) that have different data formats and interface layouts.

## Problem

Integrations built without strict, machine-readable contracts lead to non-deterministic behavior, runtime parameter mismatches, and data leakage across boundaries.

## Options Considered

1. **Custom Adapter Plugins:** Build custom integration plugins inside the Lyra repository for each consumer system. Rejected because it causes repository bloat, version lock, and deployment dependency.
2. **Dynamic AI API Calling:** Allow the AI Agent Layer to dynamically look up and call external APIs at runtime by reading dynamic OpenAPI documents without pre-registered contracts. Rejected due to latency overhead, high cost, and safety concerns (e.g. AI calling booking endpoints with invalid data).
3. **Explicit Contract Validation:** Require the consumer application to register a contract defining capabilities, inputs, output structures, and authentication expectations. Validate all capability calls against these contracts at the registry boundary. Accepted.

## Decision

All capabilities and integrations must be declared via pre-registered consumer contracts and validated using strict JSON Schema verification.

## Consequences

* **Deterministic Tool Execution:** AI agents are constrained to invoke only registered capabilities using schema-validated parameters.
* **Test Isolation:** Integration flows can be simulated and mock-tested by validating fixtures against schemas.
* **Early Failures:** Invalid parameters are caught at the Lyra boundary, protecting consumer systems from junk data.

## Future Considerations

Automate schema validation in the Capability Registry utilizing standard Python JSON Schema libraries. Log and audit all validation errors.
