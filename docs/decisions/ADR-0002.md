# ADR-0002: Why Consumer Applications Own Business Logic

## Maturity Metadata

**Status:** Approved.

**Intended Use:** Authoritative architecture decision; safe for implementation decisions within its documented scope.

## Status

Accepted.

## Context

Voice orchestration touches domain decisions such as pricing, eligibility, fulfillment, and scheduling, but those decisions vary by consumer. Lyra must remain a general orchestration platform across organizations, projects, environments, and domains.

## Problem

If Lyra embeds business rules (e.g. discount rules, cancellation fees, table booking constraints), every update to a customer's business policies would require rewriting Lyra code, playbooks, or configurations, causing deployment coupling.

## Options Considered

1. **Rule Engine in Lyra:** Embed a rule engine (e.g., executing custom scripts or JSON rules stored in Lyra) to evaluate eligibility, pricing, and availability. Rejected because it couples Lyra to the consumer's domain rules and requires constant configuration updates.
2. **Total Delegation:** Outsource the entire conversation dialog flow to the consumer. Lyra simply acts as a voice proxy. Rejected because it removes Lyra's platform value (intent extraction, prompting, multi-turn slot filling, and conversation coordination).
3. **Orchestrated Delegation:** Lyra manages the dialogue flow (prompting, slot filling, intent extraction) while delegating all business policies (pricing, slot validation, inventory, scheduling eligibility) to the consumer application via contract API calls. Accepted.

## Decision

Consumer systems remain responsible for policies, validation, pricing, eligibility, fulfillment, and domain-specific decisions.

## Consequences

* **Independent Deployments:** The consumer application can change pricing, shipping policies, or database schemas without updating Lyra playbooks or code.
* **Dialogue Consistency:** Dialogue routing, NLU extraction, and conversation state management remain standard across different business domains.
* **Integration Safety:** Lyra validates slots and values against capabilities contracts but lets the consumer determine business correctness.

## Future Considerations

Implement validation gates in the Workflow Engine to ensure that when a capability call returns a business error (e.g. "out of stock"), the engine resolves the failure state based on the playbook guidelines.
