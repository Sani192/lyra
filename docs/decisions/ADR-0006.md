# ADR-0006: Playbook Representation and Compilation

## Maturity Metadata

**Status:** Approved.

**Intended Use:** Authoritative architecture decision; safe for implementation decisions within its documented scope.

## Status

Accepted.

## Context

Lyra's Workflow Engine coordinates dialogues based on scenario-specific playbooks. The workflow engine specification (`docs/specifications/14-workflow-engine.md`) states that runtime playbooks must conform to the JSON schema (`schemas/workflow.schema.json`).

## Problem

Machine-readable JSON formats are difficult for human designers and AI coding agents to author, review, and maintain directly. Conversely, narrative text formats (such as standard Markdown playbooks under `docs/playbooks/`) are highly readable and easy to version control, but they cannot be executed directly by the Workflow Engine without high parsing latency, ambiguity, and lack of schema-level safety.

## Options Considered

1. **Runtime Markdown Parsing:** Force the Workflow Engine to parse and interpret narrative Markdown playbooks dynamically at runtime. *Rejected* because it introduces parsing overhead, non-deterministic execution paths, and bypasses schema-level validation gates.
2. **Direct JSON/DSL Authoring:** Require all playbooks to be authored directly in JSON conforming to `schemas/workflow.schema.json`. *Rejected* because it increases developer friction, reduces visibility for product owners, and increases the likelihood of syntax errors.
3. **Markdown-to-JSON Compilation (Build/Deploy-time):** Author and maintain playbooks in a structured Markdown format (with standardized sections for goals, steps, capabilities, and recovery). Implement a build-time compiler tool to translate these Markdown playbooks into executable JSON workflows that are validated against `schemas/workflow.schema.json` before release. *Accepted*.

## Decision

Playbooks will be authored and versioned in structured Markdown format. A compilation process will run during build/deployment to translate these Markdown playbooks into executable JSON files that strictly conform to `schemas/workflow.schema.json`.

## Consequences

* **Authoring Simplicity:** Humans and AI agents can easily write and update playbooks using standard Markdown.
* **Schema Safety:** The engine runs verified JSON workflows, ensuring parameter compatibility and structural validity.
* **Build Dependency:** Introduces a compilation step. The platform must implement a playbook compiler in a future phase (under `tools/` or `scripts/`).
* **Format Standardization:** Markdown playbooks must adhere to a strict structured format (headers, list prefixes) so they can be parsed deterministically by the compiler.
